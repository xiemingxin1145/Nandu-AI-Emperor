# 《南渡》AI 原生世界架构

## 目标

《南渡》不是“NPC 接一个聊天框”，而是让整个历史世界在玩家不操作时也继续运转。玩家控制宋廷，金国、地方势力、将领与文官拥有自己的判断与行动。

核心原则只有一句：**代码负责现实，AI 负责灵魂。**

## 1. 权威世界状态（Source of Truth）

以下内容永远由本地规则和存档持有，大模型没有直接写权限：

- 城池归属、城防、粮草、人口、金钱
- 军团位置、兵力、士气、补给、路线、目标
- 人物位置、身份、官职、存亡
- 地图邻接、行军耗时、天气与季节
- 战斗伤亡、攻城结果、城池易手

模型说“某军瞬移临安”不会让临安发生任何变化。模型只能提交动作，最终由移动、补给、战争系统验证和执行。

## 2. Stage 6：World Engine

Stage 6 建立了世界 AI 的基本闭环：

`World snapshot -> 一次低成本模型调用 -> WorldAction -> 本地规则校验 -> 执行 -> 战报`

任何 OpenAI-compatible 中转都可以使用；模型超时、返回坏 JSON 或未配置时，游戏降级到本地启发式策略，不阻塞回合。

## 3. Stage 7：Faction Brain

Stage 7 不再把整个敌国当成“随机选择一个目标的电脑玩家”。每个非玩家势力先独立评估自己的局势：

`Threat -> Supply -> Current Campaign -> Opportunity -> Candidate Plans -> Score`

### 战略意图

- `DEFEND`：己方要地受威胁，回援或固守
- `RESUPPLY`：补给危险，先恢复粮道
- `CONTINUE_OPERATION`：保持既定战役目标，减少每旬反复改道
- `PRESS_ADVANTAGE`：敌前已有优势，抓住决战窗口
- `RAID`：袭扰相邻薄弱目标
- `EXPAND`：局部优势明确时推进战线
- `CONSOLIDATE`：没有好机会时休整，不为“必须有动作”而送兵

每势力只向世界模型暴露少量高分候选。这样小模型只需做“军议选择题”，不用凭空设计整个战争计划，token 更少，幻觉空间也更小。

## 4. 为什么便宜模型也能玩

模型不负责：

- 算伤害
- 算路线
- 算粮草
- 判断城池是否合法
- 修改兵力
- 修改人物位置

模型主要负责：

- 在几个合理战略之间选择
- 根据人物性格与政治环境表达理由
- 产生上奏、警告、请命等叙事内容
- 后续阶段在长期目标与外交选择之间权衡

即使模型能力一般，底层世界仍遵守规则；即使模型完全离线，本地 Faction Brain 也能继续推动局势。

## 5. 战役连续性

传统“每回合重新想一次”的 AI 很容易抽风：这一旬打淮西，下一旬突然回开封，再下一旬又改江南。

Stage 7 把正在 `MARCHING` / `ENGAGEMENT_PENDING` 的军团视为已有战役承诺。只要目标仍是敌方、补给没有崩溃，就给“延续既定战役”额外优先级；只有出现重大威胁、粮道崩溃或战机明显变化时才应改计划。

## 6. 开源项目的研究边界

本架构研究过成熟开源策略游戏的公开设计思路，但《南渡》实现保持独立：

- `wangdl2005/Baye`：参考传统三国 SLG 的回合/命令队列思路；仓库无明确许可证，不复制其代码和素材。
- `zhs007/sanguo`（MIT）：参考数据驱动、人物/世界管理的分层思想。
- `yairm210/Unciv`（MPL-2.0）：参考成熟 4X 游戏将回合管理、威胁评估、外交、城市与单位自动化分层的思想。

目标是学习架构，而不是复制具体实现。

## 7. 后续路线

### Stage 7.1
- 候选战略直接约束远程模型输出
- 势力级募兵、调粮、组军与换帅
- 战略预算：军费、粮草、预备队

### Stage 8 Character Agents
- 人物长期目标
- 主动上奏、请命、争权、结党
- 人物之间主动通信与协作

### Stage 9 Information Fog
- 势力只能根据自己掌握的情报决策
- 斥候、密信、俘虏、商旅形成情报来源
- 允许误判与欺骗，但禁止全图作弊

### Stage 10 Long-term Memory
- 记录败仗、强敌、背叛、盟约与玩家承诺
- 战略 AI 根据历史经验调整风险偏好
- 让“上一次顺昌强攻惨败”真正影响下一次金军决策
