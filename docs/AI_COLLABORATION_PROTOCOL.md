# 《南渡无悔》AI 协作与交接协议

> 所有协作者的共同目标是：先做成一个真实、可玩、可持续迭代的皇帝模拟，而不是分别展示几个互相矛盾的 Demo。

## 1. 分工和权限

### 用户：项目负责人、总导演、历史与审美最终裁决

- 决定版本目标、优先级、人物设定、真实手机体验与美术/音乐是否通过。
- 批准正式地图、BGM、版本发布与分支合并。
- 提供设备反馈、截图、录像、模型/中转配置和体验问题。

### Claude：成块系统施工与权威规则

- 历史事件触发器、人物生命周期、官职履历、旅行/位置、军团、敌国 AI、活世界和事件状态机。
- 朝议卡死等状态机缺陷的底层根因修复。
- 每项系统改动必须带双路径历史回归、资源/状态约束与完整 JVM 测试。
- 不自行决定发布版本、不覆盖其他分支 UI、不一次性写入未审核的 35 名候选人物。

### Work / Codex：项目集成、复现、交互、仓库治理与 QA

- 维护总纲、执行看板、风险表、真机矩阵、版本规则和跨分支交接。
- 审查并选择性集成独立 PR；保留其他 AI 的有效记录，不整包覆盖旧基线历史。
- 修复已授权的 UI/路由/资源接线问题，检查双 GitHub Actions、固定签名、JVM 报告和 APK 内容。
- 没有玩家批准不合 main，不把未真机验证项目写成 `DONE`。

### 豆包：已批准需求下的素材生产

- 人物定装、立绘、表情、CG、地图视觉补充、旁白、环境音、音效和视频素材。
- 交付明确文件路径、manifest、来源、人物身份、历史时间、画风、音频格式和 QA 结果。
- 禁止改核心架构、虚构历史人物身份、替换固定签名、生成假 BGM 或未批准地覆盖既有资源。

## 2. 文件所有权与并行避让

开始任务前声明：

```text
任务 ID：
基线分支 / commit：
负责人：
允许修改的文件：
其他协作者正在修改的文件：
状态系统 / 资源 / UI 的接口：
预期交接与 Draft PR：
```

重点共享文件：

- `docs/PROJECT_MASTER_PLAN.md`、`docs/PROJECT_EXECUTION_BOARD.md`：由集成负责人人工保留所有有效状态，禁止“采用当前分支整份文件”解决冲突。
- `EventDirector.kt`、`StoryEventLoader.kt`、`StoryEventEffectApplier.kt`：历史逻辑负责人优先；UI 任务不得顺手重写。
- `WorldAiTurnExecutor.kt`、`ImperialMandate.kt`、`GameSaveCodec.kt`：规则、授权和存档负责人优先；地图/素材任务不得越界。
- `MainActivity.kt`、`EmperorMainScreen.kt`、正式地图页面：按任务切分入口和接口，先说明冲突策略。
- `app/build.gradle.kts`、`tools/signing/`：只有已授权的发布任务能修改版本或签名策略。

## 3. 开工流程

1. 按顺序读取 `AGENTS.md`、`START_HERE.md`、`docs/PROJECT_MASTER_PLAN.md`、`docs/PROJECT_EXECUTION_BOARD.md`、`docs/RELEASE_POLICY.md` 和任务专项。
2. 读取正式分支/PR 状态，确认目前是否已经集成；不得从旧 APK 描述倒推出当前代码。
3. 优先执行唯一 `NEXT`。用户明确重新排序时，先更新执行看板，再开始实现。
4. 标注负责人、分支、文件边界、依赖与当前证据；保持 STAB-007 与 37 项主线数字真实。
5. 用户真机反馈先整理最短复现，区分“已报告”“已复现”“已定位”“已修复”“已真机验收”。
6. 改规则时先补失败回归；改资源时先查注册表/实际路径/APK；改 UI 时保留返回、加载、错误和空状态。

## 4. 真实性硬边界

- `GameState` 是人物、城市、官职、军团、钱粮、外交和事件的唯一世界真相。
- 模型只能提出文本、建议、方案与候选行动；数值变化必须通过本地权威规则。
- 游戏定位：皇帝处理战略、任免、授权、财政尺度、外交与重大裁决；具体军政事务由获得授权的机构/官员执行。
- 模型不能直接造兵、造粮、瞬移、凭空任官、开战、复活人物或更改历史资料。
- 史实人物必须遵守出生、活动、任职、死亡、地点、阵营和旅行状态；程序生成普通人不能冒充已考证史实人物。
- 一旬尽量只做一次世界模型调用；失败、超时和坏 JSON 必须退回可用本地规则，不得锁死回合。
- 历史战役按当前敌军、城池、人物、外交和补给条件产生，禁止“到了某年自动播放”。
- 正式地图必须以真实东亚地理为底；球形泡泡图和黑底散点图不再是正式候选方案。

## 5. 提交、合流和完成

1. 独立任务默认建立独立分支和 Draft PR，base 使用指定正式集成线。
2. 只集成审查过的文件；不得引入旧基线历史、未批准地图、未批准人物或另一个任务的半成品。
3. 更新执行看板、总纲、风险文档与对应验收矩阵，标清仍需用户手机验证的项目。
4. 运行 `python3 scripts/check_project_governance.py`、现有资源守卫、完整 JVM 回归和 Android Build / Debug APK。
5. 验证固定测试签名、51 条 H.264/yuv420p/无音轨视频、54 张朝堂图、6 条旁白与 BGM 候选。
6. P0 未关闭、真机未验收、用户未批准时，不得把任务或 STAB-007 标 `DONE`，不得开启 STAB-008，不得升级或合 main。
