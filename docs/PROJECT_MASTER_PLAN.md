# 一、项目总纲

## 1. 游戏定位

《南渡无悔》不是历史剧情播放器，而是一款 **AI 原生的南宋皇帝动态历史策略沙盒**。

玩家从 1127 年建炎开局，以赵构身份执掌南宋。历史提供初始世界、人物、矛盾和潜在趋势，但后续世界必须允许被玩家和 AI 势力共同改变。

目标体验：

- 玩家下旨，世界真实响应；
- 官员有自己的位置、官职、目标、关系、记忆和利益；
- 金国、西夏、大理、高丽、草原势力、地方集团会自己行动；
- 战争不是等玩家点按钮，而是各势力真实调兵、补给、攻城、撤退；
- 历史事件可以发生，也可以因为玩家做得太好/太差而提前、延迟、变形或彻底消失；
- AI 提供“思考、表达、计划”，本地规则负责合法性和世界状态裁决；
- 玩家每一轮都应该感到：**天下自己在动，而我正在改变它。**

## 2. 核心设计原则

### 2.1 历史锚点，不是历史铁轨

历史事件使用：

`时间窗口 + 世界条件 + 人物条件 + 战争条件 + 抑制条件 + 替代事件`

而不是：

`到了某年某月 -> 强制播放固定剧情`

示例：

顺昌之战不能写成“1140 自动发生”。它应该要求：

- 时间进入合适窗口；
- 金军仍具备南侵能力；
- 金军确实沿对应战略方向推进；
- 顺昌仍是有意义的战略节点；
- 宋方有相应守军/将领；
- 相关人物存活且未被调往完全不同战区；
- 玩家没有提前改变到使这场战役失去条件。

如果金国早已被打残，则顺昌之战应被抑制，并由“北伐窗口”“金廷议和”“河南收复”等替代事件接管。

### 2.2 世界状态是唯一真相源

UI 不得硬编码人物官职、所在地、兵力、战役年份、城市归属。

所有展示必须来自状态系统：

- 人物：官职 / 所属机构 / 所在地 / 军团 / 生死 / 忠诚 / 野心 / 派系 / 关系 / 健康 / 年龄；
- 军事：军团 / 统帅 / 士兵 / 士气 / 粮草 / 行军 / 补给线 / 战区；
- 城市：归属 / 城防 / 人口 / 粮 / 商贸 / 治安 / 灾害；
- 朝廷：派系 / 官职 / 任免 / 奏疏 / 决策后果；
- 外交：关系 / 条约 / 战争状态 / 使节 / 贸易；
- 历史：已发生 / 被抑制 / 被替代 / 已偏离。

### 2.3 玩家决策必须回写世界

禁止只在 UI 局部设置 `moraleBoost = 15` 或显示一句“准奏”就算完成。

任何决策必须通过统一命令/规则入口写回 GameState，并形成：

即时效果 + 延迟效果 + 人物反应 + 世界后果 + 记录。

### 2.4 正式入口不能是空壳

正式页面必须有真实内容或明确空状态。

禁止：

- “待办 1 件”但进去一片空白；
- 有按钮但点了没有世界后果；
- 测试场景永久挂在皇宫主页；
- 资源播放失败时统一谎报“编码不兼容”。

### 2.5 AI 不直接改世界

AI 可以：

- 生成战略建议；
- 生成 NPC 奏议；
- 生成派系计划；
- 生成外交措辞；
- 生成候选行动；
- 生成历史偏离后的叙事解释。

AI 不可以绕过本地规则直接写数值或生成非法行动。

# 九、任务更新规则

每完成一项任务，执行者必须同时修改本文件：

1. 把状态从 `NEXT/IN_PROGRESS` 改成 `DONE`；
2. 在“完成记录”写：
   - 日期；
   - 分支；
   - commit / PR；
   - 测试；
   - APK/真机结果；
   - 遗留问题；
3. 更新该里程碑的“已完成 / 剩余”；
4. 更新文档顶部“当前下一任务”；
5. 将下一项 `TODO` 改为 `NEXT`；
6. 如果用户改变路线，先修改总纲，再动代码。

禁止：

- 做完代码不更新路线图；
- 为了显得进度快，把未测试任务标 DONE；
- 一个 AI 自己新开完全不同路线而不记录；
- 重复实现已经 DONE 的系统；
- 把测试 Demo 当正式玩法继续堆功能。
