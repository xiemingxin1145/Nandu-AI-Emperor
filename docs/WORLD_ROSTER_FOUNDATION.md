# 南渡世界人物志 / 多势力底座 V1

本文件定义 Stage 8 之后可直接接入的“天下人物志 + 动态人物 + 多势力”基础结构。

## 目标

南渡不把世界限制为少数名臣，也不把敌对世界压缩成单一“金国 AI”。世界数据库允许：

- 历史人物持续扩充到数百人；
- 虚构人物按时代、地区、职业、势力确定性生成；
- 核心人物、活跃人物、背景人物三级调度；
- 国家、朝堂派系、军镇、豪族、商团、宗教、叛军、草原部族等多层势力并存；
- 人物从“百科条目”被事件/任命/战争激活为完整 Character Agent；
- 大量背景人物不调用 LLM，避免人物越多 API 成本越高。

## 三层人物模型

### CORE
几十名最重要人物。拥有完整 Agent 状态、长期目标、关系、记忆、计划和重要事件决策。

### ACTIVE
几百名当前参与政治、战争、外交、地方治理或剧情的人物。以本地 Utility AI 为主，重大事件才进入模型批处理。

### BACKGROUND
可扩展到数千人。只保存人物志条目、身份、势力、地区、职业、状态等轻量数据，不进行逐旬 LLM 推理。

当 BACKGROUND 人物被征辟、任命、俘虏、参战、卷入事件或被玩家主动调查时，可提升为 ACTIVE；真正进入核心政治/军事舞台后再提升为 CORE。

## 人物来源

`PersonOrigin.HISTORICAL`：来自史料/剧本数据库，应保留 sourceNote 方便将来记录出处。

`PersonOrigin.GENERATED`：游戏内生成的人物。V1 使用本地确定性生成器，不依赖模型；后续模型只负责润色传记、性格与对话，不能修改人物真实身份和权威状态。

## 多势力原则

`WorldFactionRecord` 不等于“国家”。它同时能表达：

- 南宋、金、西夏、大理、高丽等国家；
- 南宋主战派、主和派等朝堂政治网络；
- 前线军镇、地方豪族、商人网络、寺院、叛军；
- 草原诸部等可以继续拆分的动态联盟。

国家内部也允许出现多个互相竞争的 faction。以后“金国南侵”不应该只是一个国家按钮，而可以由宗室、前线统帅、财政压力、贵族派系等共同形成决策。

## 与 Stage 8 的边界

本分支故意不修改 `CharacterAgentState`、`GameState`、`EmperorViewModel`、`GameSaveCodec` 和人物详情 UI，避免与 Claude 正在进行的 Stage 8 分支发生冲突。

Stage 8 合并后再做一次窄集成：

1. `GameState` 增加 `WorldRoster`；
2. 现有 Officer 与 `WorldPersonRecord` 建立稳定 ID 映射；
3. ACTIVE/CORE 人物才创建 CharacterAgentState；
4. 背景人物继续留在人物志，不进入逐旬 Agent tick；
5. 存档升级只保存实际 roster 数据和激活状态；
6. UI 增加“天下人物志”和“天下势力志”搜索页。

## 成本目标

目标不是让 1000 个人物每旬都调用模型，而是：世界中可以存在 1000–5000 个条目，通常只有十几个活跃人物在同一旬需要高质量决策。人物数量增长主要增加数据量，不应线性增加 API 费用。
