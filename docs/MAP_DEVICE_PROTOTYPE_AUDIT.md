# MAP-PROTOTYPE-INTEGRATION-001：寰宇图真机试览审计

日期：2026-08-21。独立试验分支：`feat/map-globe-device-prototype`。稳定只读基线：`integration/v1.6.2-preacceptance` 的 `28f05f67dabf42f6d3f4f030cb55a9a46ddcf5a3`。

## 挂载方式与隔离边界

在正式底部导航进入「山河」，点击右上角「寰宇试览」。试览支持拖转、双指缩放、城池点选、势力颜色、「展开山河」「收回寰宇」、页面按钮返回和 Android 系统返回。关闭后回到原样的正式山河页。

- 正式 `ui/screens/MapScreen.kt` 整个文件不修改；试验入口只挂在 `MainActivity.kt` 的山河容器。
- 独立 Draft PR 以稳定集成分支为 base，但不写入 #59、不合 main、不升版本、不推进 STAB-007。
- 只择取 Grok #65 的投影、Compose 试览和两份设计文档，不合并它以 main 为 base 的旧历史。
- 球面和平铺使用同一份 `MapData.nodes`、`MapData.roads`、`GameState.cities`、`GameState.factions` 和既有外交底图。没有第二套城池、道路、阵营或存档。
- 正式实际城池的当前归属、真实名称和都城优先；尚未进入 `GameState` 的节点只根据既有地图 `ownerHint` 显示为「疆域战略节点」，不得伪造驻军、人口或城市状态。
- 用户只看中文地名和势力名；不显示 `song`、`jin`、世界坐标、原型编号或开发提示。
- 皇帝授权、世界 AI、朝议、四季、BGM、序幕音频、历史事件和正式地图实现均保持基线原样。

## 当前正式山河页已知视觉问题

| 观察 | 对手机体验的影响 | 后续正式化处理方向 |
| --- | --- | --- |
| 同心圆/程序绘制背景容易产生占位感 | 缺少真实疆域和地理层次，首屏不像完整天下战略界面 | 基于现有六张地图底图统一镜头、疆域和图层；不新增图片前先做现有素材构图评估 |
| 地图主体占屏偏小 | 玩家需要先不断缩放才能辨识宋金对峙 | 按手机纵横比设置全局镜头，优先保证应天—江淮—中原主轴可辨 |
| 上下与侧面留白过多 | 势力疆域不连贯，天下格局被压缩成中间小块 | 统一边界、安全区和顶部/底部信息栏高度 |
| 城市标签靠得过近 | 缩小时地名重叠、点选困难 | 分级标签、碰撞规避、按缩放层级逐步揭示；必要时城点聚合 |
| 全图缩小时信息拥挤 | 军旗、商路、驻军和城市同时出现时难以阅读 | 根据政治/军事/外贸模式切换信息密度；确保触控目标独立于绘制圆点 |
| 缺少宏观势力对峙的气势 | 宋、金、西夏、大理的分布不能一眼读懂 | 使用真实城市归属驱动势力色带和重点战区，避免预制静态剧情疆界 |

## 原型具体取舍

1. 保留 Compose Canvas 2.5D 投影和约 820 毫秒球面/平铺连续过渡，不引入 3D 引擎或新依赖。
2. 球面单指拖转、双指缩放；平铺直接使用现有 16000 × 10000 摄像机坐标与真实道路网络。
3. 首都和选中城优先显示中文标签；普通城市仅在足够放大时显示，近距离标签互斥，减轻拥挤。
4. 触控命中区大于视觉圆点，最小约 22 个 Canvas 像素；不同密度设备仍须真实手机检查。
5. 势力色带由实际城市归属与已有战略节点求重心；不是精确行政疆界，不应冒充真实边境。
6. 平铺阶段仍是试览 Canvas，不直接复用正式 `MapScreen` 的操作控件；用户可随时「返回正式山河图」继续真实经营。

## 必须由手机实测的性能与交互风险

- 连续拖转/双指缩放是否稳定跟手；安卓中端机是否发生掉帧、触摸丢失或明显发热。
- 约 80 个城市节点、既有道路、渐变和真实底图叠加时，820 毫秒过渡是否卡顿。
- 不同屏幕比例下顶部势力图例、底部按钮和正式导航是否遮住可点区域。
- 地名碰撞阈值、城市命中半径和手势阈值是否适合手机实际像素密度。
- Android 返回手势是否先退出试览，再由正式山河页返回皇宫；城市归属变化后颜色是否同步。
- 用户是否认为寰宇旋转、展开、收回确实改善体验；未得到反馈前不得升级为正式地图。
